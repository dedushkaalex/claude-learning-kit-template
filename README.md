# Claude Learning Kit — Template

Шаблон репозитория для изучения технологического стека вместе с Claude Code в роли наставника, а не исполнителя.

Главное правило (см. `AGENTS.md`): **код пишете вы, агент учит, задаёт вопросы, проверяет и направляет.** По умолчанию агент не реализует функциональность за вас, не редактирует файлы приложения и не выдаёт готовые решения — он работает по одному шагу за раз и ждёт, пока вы выполните действие.

## Что входит в шаблон

- `AGENTS.md` — общий контракт с агентом: золотое правило, правило одного шага, лестница подсказок, сократический разбор, порядок проверки работы.
- `CLAUDE.md` — точка входа для Claude Code, импортирует `AGENTS.md` и указывает на скиллы ниже.
- `.claude/skills/` — учебные workflow:
  - `/learn` — начать или продолжить прохождение программы.
  - `/challenge` — проверить недавно изученную концепцию.
  - `/review` — учебный код-ревью.
  - `/debug` — направленная отладка без немедленной выдачи решения.
- `learning/` — состояние обучения, обновляется по ходу работы:
  - `curriculum.md` — что нужно изучить, в порядке зависимостей.
  - `roadmap.md` — как программа обучения ложится на реальный проект, который вы строите.
  - `progress.md` — текущая фаза/шаг.
  - `concepts.md` — уровень освоения по каждой концепции.
  - `mistakes.md` — повторяющиеся заблуждения, за которыми стоит следить.
  - `session.md` — заметки по текущей сессии/задаче.

## Как пользоваться шаблоном

1. Нажмите **Use this template** на GitHub (или `gh repo create --template <этот-репозиторий>`), чтобы создать новый репозиторий проекта.
2. Склонируйте его и откройте в Claude Code.
3. Заполните раздел с командами в конце `AGENTS.md` (install/dev/test/typecheck/lint/build), когда появится сам проект.
4. **Перед первым запуском `/learn` обязательно обсудите с агентом, что именно вы хотите изучить.** Не давайте ему угадывать. Разговор должен затронуть:
   - технологический стек и его версию (язык, фреймворк, база данных, инструменты);
   - какой проект станет учебным «полигоном» (предметная область, примерный объём, что считать «готово»);
   - вашу стартовую точку (что вы уже знаете, а что действительно новое);
   - целевую глубину освоения (например, «уверенно делать небольшие фичи самостоятельно» против «разбираться во внутренностях фреймворка достаточно, чтобы отлаживать его код»);
   - ограничения (бюджет времени, необходимость работать поверх существующей кодовой базы вместо старта с нуля, конкретные известные пробелы).
5. Попросите агента превратить этот разговор в `learning/curriculum.md` (заменив общий список фаз на программу, выстроенную по реальным зависимостям вашего стека) и `learning/roadmap.md` (связав фазы программы с конкретными вехами проекта, который вы строите).
6. Только после того как `curriculum.md` и `roadmap.md` отражают ваш реальный стек и проект, запускайте цикл через `/learn`.

## Почему сначала разговор, а не сразу генерация curriculum/roadmap

Файлы `learning/curriculum.md` и `learning/roadmap.md` в этом шаблоне по умолчанию — общие заготовки: названия фаз вроде «Core Framework» или «Persistence» без привязки к конкретному стеку. Если агент заполнит их без предварительного понимания вашей цели, бэкграунда и ограничений, он выдаст типовой, перегруженный теорией план, который не будет соответствовать ни вашему способу учиться, ни тому, что вы на самом деле строите. Короткий разговор заранее избавляет от повторного изучения уже известного материала и от пропуска предпосылок, о нехватке которых агент просто не знал.
